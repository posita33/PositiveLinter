# HTML レポートの使い方

HTML レポートでは、スキャンで見つかった指摘を一覧で確認し、重要度やアセットの種類で絞り込めます。検索、並べ替え、詳細表示、CSV 出力はブラウザー内で動作します。HTML ファイル 1 つに表示用のコードと結果をまとめているため、ネット接続やサーバーは必要ありません。

## 新しいレポートを出力する

更新した PositiveLinter を UE 5.7.4 用にビルドし、対象プロジェクトに導入してください。Unreal Editor からスキャンを実行し、結果画面の **Export To HTML** を選びます。出力された HTML を Edge や Chrome などのブラウザーで開いてください。標準の保存先は、対象プロジェクトの `Saved/LintReports` です。

Commandlet からも同じデザインのレポートを出力できます。以下は PowerShell で `MyProject.uproject` の `/Game` を UE5 ルールセットで検証する例です。エンジンとプロジェクトのパスは実際の環境に置き換えてください。

```powershell
& "C:\Program Files\Epic Games\UE_5.7\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "D:\Projects\MyProject\MyProject.uproject" -run=Linter "/Game" "-RuleSet=ue5.style" -html -unattended -nop4
```

`-html` だけを指定すると日時付きのファイル名になります。ファイル名を指定する場合は `"-html=quality-report.html"` に置き換えます。この例では `Saved/LintReports/quality-report.html` に保存され、次回も同名を指定すると上書きされます。日ごとの結果を残す場合は日時付きのファイル名を利用してください。

プラグインを更新しても、すでに保存した HTML の表示は変わりません。新たに出力するか、後述の変換スクリプトを使います。

## 一覧を確認する

画面上部で、指摘の総数、指摘のあるアセット数、エラー数、警告数を確認できます。これらは**レポート全体の集計**で、フィルター後も変わりません。絞り込み後の指摘数とアセット数は、一覧のすぐ上に表示されます。

一覧の 1 行は 1 件の指摘です。同じアセットに複数の指摘がある場合は複数行になります。アセット数はパスの重複を除いて数えます。正常なアセットは掲載しないため、この数値は検査済みアセットの総数や合格率を表しません。

| 重要度 | 表示 | 用途 |
| --- | --- | --- |
| エラー | 赤系の `⊗ エラー` | エラーとして設定されたルールの違反を確認します。 |
| 警告 | 黄系の `△ 警告` | 警告として設定されたルールの指摘を確認します。 |
| 情報 | 青系の `ⓘ 情報` | 情報として設定されたルールの通知を確認します。 |

重要度は各ルールの設定に従います。色に加えて記号と文字でも区別でき、右上のテーマ切り替えボタンでダーク／ライトを選べます。

新規レポートにはプロジェクト名、ルールセット、スキャン対象、生成日時も記録されます。生成日時は UTC で保存し、閲覧するブラウザーのタイムゾーンで表示します。旧レポートの変換では、元のデータにないルールセットやスキャン対象を、指摘されたアセットから推定しません。旧ファイル名から取得した日時にはタイムゾーン情報がないため、その旨を表示します。

## 検索・フィルター・ソート

- **検索**: アセット名、パス、クラス、ルールグループ、ルール名、説明、推奨される修正を検索します。空白で区切った複数の語は、すべての語を含む指摘に絞り込みます。入力欄以外で `/` キーを押すと検索欄に移動できます。
- **重要度**: エラー／警告／情報を選びます。上部のエラー・警告の集計や左側のメニューからも切り替えられます。
- **種類・グループ**: アセットのクラスとルールグループで絞り込みます。左側には指摘の多いルールが表示され、クリックするとそのルールの指摘を確認できます。もう一度クリックするとルールの絞り込みを解除します。
- **ソート**: 一覧の「重要度」「アセット」「種類」「ルール」をクリックします。同じ列を再度クリックすると昇順／降順が切り替わります。初期表示は重要度順です。
- **ページ**: 1 ページに 25／50／100 件を表示できます。ページを移動しても検索・フィルター・ソートは維持されます。

検索と各フィルターは同時に使えます。例えば、重要度を「警告」、種類を「Texture2D」にして `Characters` を検索すると、その語を含む Texture2D の警告だけを確認できます。**リセット**は検索と絞り込み条件を解除します。

## 詳細と CSV を使って修正する

行をクリックすると詳細パネルが開き、アセットパス、ルールの説明、推奨される修正を省略せずに確認できます。**パスをコピー**でアセットを探すためのパスを取得でき、パネル下部の矢印で絞り込み結果の前後の指摘へ移動できます。`Esc` キーで詳細を閉じます。

ルールに Web ドキュメントの URL が登録されていれば、詳細から開けます。このリンク先の閲覧にはネット接続が必要です。レポート自体は外部データを取得しません。

**CSV をエクスポート**では、現在のページだけでなく、**絞り込み後の全件**を現在の並び順で保存します。アセットパスや説明、推奨される修正も含まれるため、修正対象の共有に利用できます。UTF-8 BOM 付きで出力し、表計算ソフトが数式として解釈し得るセルには先頭に `'` を付けて保護します。

## 以前の HTML・JSON を変換する

リポジトリに含まれる [`scripts/preview-lint-report.mjs`](../scripts/preview-lint-report.mjs) は、以前の HTML レポートまたは JSON レポートから結果データを読み取り、新しいデザインの HTML を作成します。UE を起動したり再スキャンしたりする必要はありません。実行には Node.js が必要です。

リポジトリのルートで、入力ファイルと出力ファイルを指定します。

```powershell
node scripts/preview-lint-report.mjs "D:\Projects\MyProject\Saved\LintReports\lint-report-2026.09.07-21.01.06.html" ".build/report-preview/index.html"
```

出力ファイルの指定を省略した場合も、リポジトリ内の `.build/report-preview/index.html` に保存されます。元のレポートを上書きする指定は拒否されます。スクリプトは HTML 内の JSON データだけを読み、入力ファイルの JavaScript は実行しません。変換は表示と保存形式の更新であり、スキャン結果の再評価ではありません。

## 保存サイズと日々の運用

HTML 内の結果は、共通するルールや文字列を 1 回だけ保存して参照する形式です。UTF-8 を使い、外部ライブラリや外部フォントに依存せず、画像ファイルも必要ありません。元の説明や個別の修正案は保持しています。別途 **Export To JSON** で出力する JSON の形式は変更していません。

実データの変換では、**2,793 アセット・4,050 件の指摘を保持したまま、約 6.49 MB から約 0.60 MB へ約 91% 削減**しました。この規模で 1 日 1 回保存すると、年間の目安は約 220 MB です。ファイルサイズは指摘数やメッセージの内容によって増減します。

ページ分割で一度に描画する行を抑えていますが、HTML には結果の全件が入っています。画面下の「データ」サイズは埋め込み結果データの容量で、HTML ファイル全体の容量ではありません。古いレポートの自動削除や保存期限の管理は行わないため、必要に応じてプロジェクト側で保存期間を決めてください。
